# v1.3.x series (next stable)

## v1.3.0 (upcoming release)

This release brings spatially varying particulate media to Eradiate: aerosol
and cloud fields can now vary per voxel, with particle properties interpolated
over particle size distribution parameters or other state variables such as
relative humidity. To support this, the aerosol data format is generalized to
the Prt family of particle radiative property formats, and a new Ppr format
describes particle profiles. The kernel is upgraded to v0.6.0, which drops
Python 3.9 support. Testing infrastructure and the development environment are
also substantially reworked.

Most changes are backward compatible: renamed components, fields and functions
remain available with a deprecation warning until v2.0.0. Deprecation warnings
are now displayed by default.

* **Spatially varying particulate media**

  * New {class}`.ParticleStateComponent` atmosphere component. It interpolates
    particle properties linearly over 1 or 2 state variables (*e.g.* relative
    humidity) supplied per voxel by a {class}`.ParticleProfile`
    ({ghpr}`623`).
  * New {class}`.ParticlePSDComponent` atmosphere component for particulate
    media parametrized by `reff` and `veff`, like clouds ({ghpr}`605`).
  * New {class}`.GriddedParticlePhaseFunction`, used by these components. It
    wraps the `particlephase` kernel plugin and interpolates the phase matrix
    per voxel over the state variables ({ghpr}`605`).
  * {class}`.ParticleOTComponent`'s `bottom` and `top` altitudes and `tau_ref`
    can now vary per horizontal grid cell. Particle properties are the same in
    every cell ({ghpr}`603`).
  * 3D atmospheres can now clamp, repeat, or mirror samples that fall outside
    the grid extent. Set this with `SceneGeometry`'s `wrap_mode`
    ({ghpr}`604`).
  * The piecewise integrator is rejected for atmosphere grids with horizontal
    resolution ({ghpr}`623`).

* **Particle data formats and converters**

  * The `aer_core_v2` format is renamed `prt_core_v1` as part of a nomenclature
    generalization effort. Compatibility is kept ({ghpr}`599`).
  * {class}`.ParticleProperties` accepts Prt datasets with any state
    dimensions. This includes the new `prt_psd_v1` format, which extends
    `prt_core_v1` with `reff`/`veff` dimensions, and the new `prt_hum_v1`
    format, which adds a relative humidity dimension ({ghpr}`599`,
    {ghpr}`623`).
  * New `ppr_core_v1` data format for spatially varying particle profiles, and
    its `ppr_psd_v1` extension for profiles described by particle size
    distribution parameters ({ghpr}`599`, {ghpr}`623`).
  * New {func}`.libradtran_to_prt` converter, the single entry point for
    libRadtran optical property data. It accepts a path or a dataset, selects
    `reff` and `hum` with xarray semantics and returns a `prt_core_v1`,
    `prt_psd_v1` or `prt_hum_v1` dataset depending on the dimensions kept.
    `load_aerosol_libradtran()` and {func}`.libradtran_to_aer_core_v2` are
    deprecated in favour of it and will be removed in v2.0.0 ({ghpr}`623`).
  * All Prt variants are built by the new {func}`.make_prt_v1`, with
    {func}`.make_prt_core_v1`, {func}`.make_prt_psd_v1` and
    {func}`.make_prt_hum_v1` as thin wrappers ({ghpr}`623`).
  * The particle components user guide includes a terminology glossary
    (amount, field, particle profile, particle properties, state dimension,
    state variable) ({ghpr}`623`).

* **Atmosphere component API**

  * Abstract {class}`.ParticleComponent` is introduced to factorize flags
    handling in particle-related subclasses ({ghpr}`603`).
  * {class}`.ParticleLayer` is renamed {class}`.ParticleOTComponent`
    ({ghpr}`603`, {ghpr}`623`).
  * {class}`.HeterogeneousAtmosphere`'s `particle_layers` field is renamed
    `particle_components`. The old name is still accepted by the constructor
    and as a read-only attribute, with a deprecation warning; it will be
    removed in v2.0.0 ({ghpr}`603`, {ghpr}`623`).
  * New {class}`.ParticleExtinctionComponent` to define particles with an
    explicit extinction dataset and an arbitrary phase function. `sigma_t` and
    `albedo` can be passed in any dimension order ({ghpr}`603`, {ghpr}`623`).
  * `BlendPhaseFunction` is replaced by {class}`.MultiPhaseFunction`. It blends
    any number of phase functions using per-component weight grids, not nested
    pairs. Weights can also be passed as a tuple of callables ({ghpr}`587`,
    {ghpr}`623`).
  * {class}`.HeterogeneousAtmosphere` components now warn when `use_rrt`,
    `ddis_threshold`, `force_majorant` or `extremum_resolution` are set on
    them: these fields are ignored for nested components and must be set on
    the parent ({ghpr}`623`).
  * The unused `eval_mfp()` method is removed from all atmosphere classes
    ({ghpr}`623`).

* **Monte Carlo integration**

  * ⚠️ In CKD mode, {attr}`.Measure.spp` is now the sample count spent on each
    output value rather than on each spectral loop iteration: it is split
    across the g-points of each bin proportionally to quadrature weights and,
    with a {class}`.BandSRF`, across bins proportionally to the SRF weights
    applied by the post-processing pipeline, which makes per-bin results
    (*e.g.* `radiance`, as opposed to `radiance_srf`) noisier in low-weight
    bins. Every spectral loop iteration gets at least 1 sample: in CKD mode,
    `spp` must be at least 1 per g-point (per bin and g-point with a
    {class}`.BandSRF`), lower values raise a `ValueError`. Mono mode is
    unchanged. The previous behaviour is restored by setting
    {attr}`.Measure.spp_allocation` to `"uniform"`, or globally with
    `sample_allocation = "uniform"` in the configuration file or the
    `ERADIATE_SAMPLE_ALLOCATION` environment variable. The sample counts
    actually rendered for each spectral loop iteration are stored in
    {attr}`.Measure.mi_results`: samplers other than `"independent"` round
    them up (see {func}`.kernel.effective_spp`). The
    allocation policy is recorded in the `sample_allocation` attribute of
    results.
    See {ref}`sec-user_guide-spectral_discretization-sample_allocation`.
  * The variance computed from second moments is clamped at zero, which
    removes negative round-off residuals for noiseless results.
  * ⚠️ The variance computed from second moments uses the unbiased estimator
    (division by `spp - 1` instead of `spp`) and is NaN where fewer than 2
    samples were taken.
  * {class}`.EOVolPathIntegrator` exposes the `use_ddis`, `use_ddis_surface`,
    `use_pbs` and `use_nle` flags. `use_vroom` is true when all three of DDIS,
    PBS and NLE are enabled; setting it sets all three ({ghpr}`623`).
  * Fixed the `extremum_spherical` transform and parameters in spherical shell
    geometry ({ghpr}`623`).
  * Fixed an `AttributeError` raised when `extremum_resolution` is set with the
    default integrator. A warning is now emitted when a piecewise medium drops
    the extremum structure ({ghpr}`623`).

* **Kernel and Python support**

  * The kernel is upgraded to v0.6.0 ({ghpr}`621`). This notably enables
    support for Python 3.14 (natively) and 3.15 (through the 3.12 stable ABI).
    We however recommend Python 3.10 to 3.14.
  * ⚠️ Python 3.9 and macOS x64 support are dropped as a consequence of the
    kernel upgrade ({ghpr}`621`).
  * 🖥️ Traversal logic of the Mitsuba scene is moved to the kernel code
    ({ghpr}`593`).
  * ⚠️🖥️ {func}`.mi_render` maps each context and sensor to a `(bitmap, spp)`
    pair instead of a bitmap, where `spp` is the sample count actually
    rendered. A sample count override no longer persists in the sensor's
    sampler after rendering.

* **Results and performance**

  * Results now include the SRF-weighted variance `<var>_srf_var` alongside
    `<var>_srf` whenever variance computation is enabled. This makes
    noise-aware comparisons (*e.g.* {class}`.ZTest`) possible on
    band-integrated quantities ({ghpr}`595`).
  * Various fixes on data caching and inappropriate usage of Pint and xarray
    provide significant speedup on the spectral loop and post-processing
    pipeline ({ghpr}`614`, {ghpr}`620`).
  * New {func}`.magnitude_as` returns the magnitude of a value in target units
    without building an intermediate quantity for unitless input. Pint usage
    is aligned with best practices across the codebase ({ghcommit}`267cd738`).

* **Error handling and deprecation**

  * ⚠️ {class}`.DeprecatedWarning` now subclasses `FutureWarning` instead of
    `DeprecationWarning`. Deprecation warnings are therefore displayed by
    default, including when deprecated arguments are passed through factories
    (*e.g.* dictionary-based scene specifications) ({ghpr}`623`).
  * ⚠️ Fixed exceptions raised with an incorrect type or an ill-formed message
    across the codebase. Notable changes that can have (unlikely) consequences
    for callers ({ghpr}`615`):

    * {func}`.supported_mode` and {func}`.unsupported_mode` raise
      {class}`.UnsetModeError` if no mode is active.
    * Converting a dict with no `type` entry through a factory raises a
      `ValueError` instead of a `KeyError`.
    * In {meth}`.AbstractHeterogeneousAtmosphere.eval_transmittance`, errors
      raised during extinction coefficient evaluation were confused with an
      invalid interaction type: this is no longer the case.
    * Validators of {class}`.RTLSBSDF` and the atmosphere/canopy size check in
      {class}`.CanopyAtmosphereExperiment` raise `ValueError` instead of using
      `assert`.
    * Type-related errors now raise `TypeError` (unhandled geometry types,
      {meth}`.SpectralIndex.convert`); value-related errors now raise
      `ValueError` (*e.g.* mismatching dimensions in variance computation, leaf
      cloud parameter set).

  * Unused exception classes `KernelVariantError`, `InterpolationError`,
    `MissingCoordinateError`, `ScalarCoordinateError` and
    `OutOfBoundsCoordinateError` are removed ({ghpr}`615`).
  * 🖥️ New `renamed_kwargs()` class decorator in
    {mod}`eradiate.util.deprecation` to deprecate renamed constructor arguments
    of attrs classes ({ghpr}`623`).
  * 🖥️ Deprecated components always show the deprecation notice in their
    docstrings, including in documentation built from development versions
    ({ghpr}`623`).

* 🖥️ **Testing infrastructure**

  * ⚠️ The `eradiate.test_tools` package is renamed {mod}`eradiate.testing`
    ({ghcommit}`6b41072c`).
  * Regression reference data management is now handled by
    [pytest-regressions](https://pytest-regressions.readthedocs.io) through the
    new `dataset_regression` fixture, and is decoupled from the statistical
    testing framework. {class}`.RegressionTest` subclasses no longer manage
    data and only perform comparison and plotting ({ghpr}`596`).
  * The `--update-references` flag is replaced by pytest-regressions'
    `--force-regen` and `--regen-all`. Missing reference data remains an error
    unless one of these flags is passed. Regenerated references are now
    written to the `eradiate-data` submodule (overridable) instead of the
    artefact directory ({ghpr}`596`).
  * {class}`.RegressionTest` can now evaluate its testing criterion
    independently for each slice of a dimension (specified with a `dim`
    parameter) and reports the worst one. This replaces per-wavelength loops
    found in some tests and is stricter than comparing flattened arrays
    ({ghpr}`596`).
  * Regression test artefacts are no longer prefixed with a session timestamp;
    they are named after their reference dataset ({ghpr}`596`).
  * {class}`.RegressionTest` no longer raises when initialized with plotting
    enabled and no reference data ({ghpr}`582`).
  * Test code no longer depends directly on Robot Framework. Report messages
    are routed through {class}`.ReportLogger`, which falls back to standard
    logging when Robot is not installed. Robot Framework is no longer a docs
    dependency ({ghpr}`582`).
  * Test report products (`output.xml`, `log.html`, `report.html` and PDF
    renders) are now written to the `reports/` directory. `figure_to_html()`
    is moved from `test_tools.regression` to `test_tools.report`
    ({ghpr}`582`).
  * RAMI4ATM regression tests are refactored and references regenerated with
    a low variance ({ghpr}`598`).
  * Particle component tests are grouped in class suites ({ghpr}`623`).
  * Pytest default verbosity level is increased to `-vv` ({ghpr}`580`).
  * Added `pytest-regressions` and `colorcet` dependencies in the testing
    environment ({ghpr}`596`).

* 🖥️ **Development environment and documentation**

  * The `dev` env is deprecated. The `default` env is now used for local
    builds. The `docs` env is used both locally and online to compile the
    documentation. The `prod` env is gone, replaced by the already existing
    `pyxxx` environments ({ghpr}`580`).
  * Documentation now builds with Sphinx 9 and Python 3.11. The local docs
    build mocks Mitsuba and Dr.Jit like the Read The Docs build does
    ({ghpr}`580`).
  * Tutorials are moved to the `docs/tutorials` subdirectory ({ghpr}`580`).
  * Tool configuration is moved to external files to unclutter
    `pyproject.toml` ({ghpr}`580`).
  * The codebase and tooling were adjusted to better comply with the
    [Scientific Python Library Development Guide](https://learn.scientific-python.org/development/)
    ({ghpr}`583`).
  * Hardened Ruff linter and formatter settings, and applied a pass over the
    whole codebase ({ghpr}`617`).
  * The data and tutorials submodules are updated: revised polarization
    tutorial and regenerated IPRT datasets ({ghpr}`623`).
  * Fixed multiple breakages after a development environment update
    ({ghpr}`578`).

* 🖥️ **Internal refactoring**

  * `ZGrid` is replaced throughout the atmosphere stack by the new `grid.py`
    facility (`SpatialGrid`, `CartesianGrid`, `SphericalGrid`) and a
    `generate_gridvolume()` helper for building kernel volumes ({ghpr}`600`).
    Grid accessors use axis-first names aligned with dataset naming
    (`x_edges`, `x_centers`, `n_x_cells`, *etc.*), factories are defined on
    `CartesianGrid` and `SphericalGrid`, and copies are resampled with
    `with_cell_counts()`/`with_cell_sizes()` ({ghpr}`623`).
  * `RayleighPhaseFunction` now builds its depolarization-factor volume with
    `generate_gridvolume()`, instead of hand-rolled `DictParameter`/
    `SceneParameter` code ({ghpr}`587`).
  * `ArrayParticleDistribution` now accepts 3D arrays (one per horizontal
    cell), not just 1D ({ghpr}`603`).
  * Duplicate phase template methods are removed from
    {class}`.HeterogeneousAtmosphere` ({ghpr}`623`).
  * Compatibility shims are grouped in a dedicated module ({ghpr}`618`).
  * Various code import cleanup actions ({ghpr}`619`).

* **Various minor fixes**

  * Fixed a bug where spheroidal particle datasets would raise an `IndexError`
    upon a call to `ParticleProperties.eval_phase()` in polarized mode
    ({ghpr}`594`).
  * Fixed {class}`.SphericalShellGeometry` placing volume data incorrectly
    when config and kernel length units differ ({ghcommit}`d756860b`).
  * Fixed Skyfield data expiry warnings making tests fail; Skyfield logic is
    moved to a private module ({ghcommit}`d596502b`).
