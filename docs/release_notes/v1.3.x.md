# v1.3.x series (next stable)

## v1.3.0 (upcoming release)

### Removed

* Python 3.9 support is dropped. This is a consequence of the kernel upgrade to
  0.6.0 ({ghpr}`621`).
* The unused `eval_mfp()` method is removed from all atmosphere classes
  ({ghpr}`623`).

### Added

* Results now include the SRF-weighted variance `<var>_srf_var` alongside
  `<var>_srf` whenever variance computation is enabled. This makes
  noise-aware comparisons (*e.g.* {class}`.ZTest`) possible on band-integrated
  quantities ({ghpr}`595`).
* The `aer_core_v2` format is renamed `prt_core_v1` as part of a nomenclature generalization effort. Compatibility is kept ({ghpr}`599`).
* {class}`.ParticleProperties` can now load particle radiative property
  datasets in the new `prt_psd_v1` format, which extends `prt_core_v1` with
  `reff`/`veff` support ({ghpr}`599`).
* New `pfd_core_v1` data format for spatially varying particle profiles, like
  clouds, and its `pfd_psd_v1` extension for profiles described by particle
  size distribution parameters ({ghpr}`599`).
* Abstract {class}`.ParticleComponent` is introduced to factorize flags handling
  in particles related subclasses ({ghpr}`603`).
* {class}`.ParticleLayer` is renamed {class}`.ParticleOTComponent` ({ghpr}`603`).
* {class}`.ParticleOTComponent`'s `bottom` and `top` altitudes can now vary per
  horizontal grid cell. `tau_ref` can vary per cell too. Particle properties
  are the same in every cell ({ghpr}`603`).
* {class}`.ParticleExtinctionComponent` allows to define particles with an explicit
  dataset of extinction and an arbitrary phase function. ({ghpr}`603`).
* 3D atmospheres can now clamp, repeat, or mirror samples that fall outside
  the grid extent. Set this with `SceneGeometry`'s `wrap_mode`
  ({ghpr}`604`).
* New {class}`.ParticleStateComponent` implements a generic particle to profile
  linear interpolation scheme.
* New {class}`.ParticlePSDCompponent` atmosphere component for spatially varying
  particle fields, like clouds. It uses a {class}`.ParticleProfile`, and its
  phase function, the new ({ghpr}`605`).
  {class}`.GriddedParticlePhaseFunction`, wraps the `particlefieldphase` kernel
  plugin and interpolates the phase matrix per voxel over `(r_eff, v_eff)`
  ({ghpr}`605`).

### Changed

* `BlendPhaseFunction` is replaced by {class}`.MultiPhaseFunction`. It blends
  any number of phase functions using per-component weight grids, not nested
  pairs ({ghpr}`587`).
* {class}`.HeterogeneousAtmosphere`'s `particle_layers` field is renamed
  `particle_components`. The old name is still accepted by the constructor and
  as a read-only attribute, with a deprecation warning; it will be removed in
  v2.0.0 ({ghpr}`603`).
* The kernel is upgraded to v0.6.0 ({ghpr}`621`). This notably enables support
  for Python 3.14 (natively) and 3.15 (through the 3.12 stable ABI). We however
  recommend Python 3.10 to 3.14.

### Fixed

* 🖥️ Fixed multiple breakages after a development environment update ({ghpr}`578`).
* 🖥️ {class}`.RegressionTest` no longer raises when initialized with plotting
  enabled and no reference data ({ghpr}`582`).
* Fixed a bug where spheroidal particle datasets would raise an `IndexError`
  upon a call to `ParticleProperties.eval_phase()` in polarized mode
  ({ghpr}`594`).
* Performance improvements: various fixes on data caching and inappropriate
  usage of Pint and xarray provide significant speedup on the spectral loop and
  post-processing pipeline ({ghpr}`614`).
* ⚠️ Fixed exceptions raised with an incorrect type or an ill-formed message
  across the codebase. Notable changes that can have (unlikely) consequences for
  callers:

  * {func}`.supported_mode` and {func}`.unsupported_mode` raise
    {class}`.UnsetModeError` if no mode is active.
  * Converting a dict with no `type` entry through a factory raises a
    `ValueError` instead of a `KeyError`.
  * In {meth}`.AbstractHeterogeneousAtmosphere.eval_transmittance`, errors
    raised during extinction coefficient evaluation were confused with an
    invalid interaction type: this is not longer the case.
  * Validators of {class}`.RTLSBSDF` and the atmosphere/canopy size check in
    {class}`.CanopyAtmosphereExperiment` raise `ValueError` instead of using
    `assert`.
  * Type-related errors now raise `TypeError` (unhandled geometry types,
    {meth}`.SpectralIndex.convert`); value-related errors now raise
    `ValueError` (*e.g.* mismatching dimensions in variance computation, leaf
    cloud parameter set).

### Removed

* Unused exception classes `KernelVariantError`, `InterpolationError`,
  `MissingCoordinateError`, `ScalarCoordinateError` and
  `OutOfBoundsCoordinateError` are removed.

### Internal changes

* 🖥️ `ZGrid` is replaced throughout the atmosphere stack by the new
  `grid.py` facility (`SpatialGrid`, `CartesianGrid`,
  `SphericalGrid`) and a `generate_gridvolume()` helper for
  building kernel volumes ({ghpr}`600`).
* 🖥️ `RayleighPhaseFunction` now builds its depolarization-factor volume with
  `generate_gridvolume()`, instead of hand-rolled `DictParameter`/
  `SceneParameter` code ({ghpr}`587`).
* 🖥️ `ArrayParticleDistribution` now accepts 3D arrays (one per horizontal
  cell), not just 1D ({ghpr}`603`).
* 🖥️ Documentation now builds with Sphinx 9 and Python 3.11 ({ghpr}`580`).
* 🖥️ Local docs build now mocks Mitsuba and Dr.Jit like the Read The Docs build
  does ({ghpr}`580`).
* 🖥️ The `dev` env is now deprecated. The `default` env is now used for local
  build. The `docs` env is used both locally and online to compile the
  documentation. The `prod` env is gone, replaced by the already existing
  `pyxxx` environments ({ghpr}`580`).
* 🖥️ Pytest default verbosity level increased to `-vv` ({ghpr}`580`).
* 🖥️ Tool configuration moved to external files to unclutter `pyproject.toml`
  ({ghpr}`580`).
* 🖥️ Tutorials moved to the `docs/tutorials` subdirectory ({ghpr}`580`).
* 🖥️ The codebase and tooling were adjusted to better comply with the
  [Scientific Python Library Development Guide](https://learn.scientific-python.org/development/)
  ({ghpr}`583`).
* 🖥️ Test code no longer depends directly on Robot ({ghpr}`582`).
* 🖥️ Report messages are now routed through {class}`.ReportLogger`, which falls
  back to standard logging when Robot is not installed ({ghpr}`582`).
* 🖥️ Robot Framework is no longer a docs dependency ({ghpr}`582`).
* 🖥️ Test report products (`output.xml`, `log.html`, `report.html` and PDF
  renders) are now written to the `reports/` directory ({ghpr}`582`).
* 🖥️ Move `figure_to_html()` from `test_tools.regression` to `test_tools.report`
  ({ghpr}`582`).
* 🖥️ Move traversal logic of the mitsuba scene in the kernel code ({ghpr}`593`).
* 🖥️ Regression reference data management is now handled by
  [pytest-regressions](https://pytest-regressions.readthedocs.io) through the
  new `dataset_regression` fixture, and is decoupled from the statistical
  testing framework. {class}`.RegressionTest` subclasses no longer manage data
  and only perform comparison and plotting ({ghpr}`596`).
* 🖥️ The `--update-references` flag is replaced by pytest-regressions'
  `--force-regen` and `--regen-all`. Missing reference data remains an error
  unless one these flags is passed. Regenerated references are now written to
  the `eradiate-data` submodule (overridable) instead of the artefact directory
  ({ghpr}`596`).
* 🖥️ {class}`.RegressionTest` can now evaluate its testing criterion
  independently for each slice of a dimension (specified with a `dim` parameter)
  and reports the worst one. This replaces per-wavelength loops found in some
  tests and is stricter than comparing flattened arrays ({ghpr}`596`).
* 🖥️ Regression test artefacts are no longer prefixed with a session timestamp;
  they are named after their reference dataset ({ghpr}`596`).
* 🖥️ Added `pytest-regressions` and `colorcet` dependencies in the testing
  environment ({ghpr}`596`).
* 🖥️ RAMI4ATM regression tests are refactored and references regenerated with a
  low variance ({ghpr}`598`).
* 🖥️ Hardened Ruff linter and formatter settings, and applied a pass over the
  whole codebase ({ghpr}`617`).
* 🖥️ Various code import cleanup actions ({ghpr}`619`).
* 🖥️ Group compatibility shims in a dedicated module ({ghpr}`618`).
* 🖥️ Streamlined usage of Pint throughout the whole codebase to minimize the
  performance overhead ({ghpr}`620`).
* 🖥️⚠️  The `eradiate.test_tools` package is renamed {mod}`eradiate.testing` ({ghcommit}`6b41072c`).
